# Relecture et corrections de la PR #1

25 octobre 2026 — [PR concernée](https://github.com/ErwanMouras/basket-ai-analysis/pull/1).

La relecture porte sur le code de la PR, les contrats de sortie, les parcours
Docker et les commandes documentées. Les corrections sont accompagnées de tests
qui reproduisent les défauts trouvés.

## Corrections

| Problème | Correction |
| --- | --- |
| Un export remplacé pendant une évaluation ballon pouvait ne pas être détecté | Relire le manifeste et la sélection avant de publier les métriques ; refuser les sélections vides et les sorties qui chevauchent le dataset |
| Une annotation gold modifiée pendant le calcul pouvait produire un rapport devenu impossible à reproduire | Revérifier les empreintes en fin d'évaluation et inclure le code de la politique d'identité dans le gel |
| La promotion pouvait utiliser un rapport différent des preuves du candidat enregistré | Comparer modèle, métriques, protocole, référence et run avec la provenance enregistrée avant de modifier l'alias |
| Les identités finales et abstentions n'étaient pas interprétées de façon identique par tous les rapports | Réutiliser la politique d'identité du moteur de distance dans le gold et le bilan de disponibilité |
| Un bundle ballon pouvait passer la vérification sans son code TrackNet | Exiger le checkout et sa révision ; refuser les backends personnes absents du runtime CPU portable |
| Un seek placé exactement sur une frontière pouvait afficher l'image précédente | Viser l'intérieur de la frame et restaurer immédiatement les calques en cache ; utiliser le temps source pour les sauts d'une seconde |
| Une erreur réseau d'un ancien run pouvait perturber le run courant | Ignorer les réponses périmées, y compris leurs effets sur le cache |
| Une distance était affichée sans durée ni couverture | Ajouter les deux mesures, calculer la couverture sur les durées agrégées et rendre la fiche défilable sur petit écran |
| Le cas synthétique ne respectait pas tous les champs du schéma annoncé | Compléter points au sol, source et capacités ; conserver son caractère scripté dans les limitations et le manifeste |

Les archives source incluent aussi `.gitattributes`, et le script de configuration
R2 affiche désormais la commande DVC réellement disponible.

## Vérifications exécutées

- **338 tests Python réussis, 28 optionnels ignorés**, depuis une extraction
  propre de Git dans l'environnement CPU.
- **7 tests JavaScript réussis**, ajoutés au runner utilisé par la CI, et
  vérification de syntaxe réussie.
- Lecture réelle dans Chromium : fiche joueur conforme aux statistiques,
  lecture/pause, seek, calibration indisponible, coupe caméra, filtres et
  changement de run avec réponse réseau retardée. Aucune erreur JavaScript.
- Affichages vérifiés à 1440 × 1000, 1024 × 768 et 375 × 812 : absence de
  débordement horizontal et note de couverture accessible.
- Validation JSON Schema des 180 observations et des statistiques du cas public,
  d'un cas nouvellement généré et des sorties réelles du conteneur CPU.
- Bundle local vérifié, image runtime reconstruite et **inférence CPU hors réseau
  terminée sur six frames**, avec joueurs, arbitres, ballon, terrain, pose et OCR
  actifs. Le bilan d'intégrité compte les mêmes six frames.
- Liens documentaires et `git diff --check` contrôlés.
